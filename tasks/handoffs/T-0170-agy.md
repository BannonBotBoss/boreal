## What Was Built

1. **Landed-site longitude helper (`src/core/sitePhase.ts`)**:
   - Added `siteLongitude(homeLon: number)` alongside `siteLatitude(homeLat: number)` returning `Number.isFinite(SITE.lonDeg) ? SITE.lonDeg : homeLon`, so consumers read the active landed site longitude without duplicating `NaN` checks.
2. **Seasonal & landed-latitude Chronometer dial and readout (`src/ui/chronometer.ts`)**:
   - Added pure helpers `dialGradient(day, lat)` and `chronoSunState(timeSec, homeLat = WEATHER_SITE.lat)` reading `hourAt(timeSec)`, `dayAt(timeSec)`, and `siteLatitude(homeLat)` into `sunPosition(hour, day, lat)`.
   - Cached `dial.style.background` by `${Math.floor(s.day)}:${s.lat.toFixed(4)}` inside `draw()` so the 24-hour conic-gradient day-length arc updates immediately across dates (`?day=`, `?date=`, midnight rollover) and remote globe landings (`setSite` / `clearSite`) without rebuilding DOM CSS gradients on unchanged frames.
3. **Landed-site topocentric Venus sky state (`src/render/venusSky.ts`)**:
   - Added `siteVenusSky(date, hour)` resolving `lat = siteLatitude(SITE.lat)` and `lon = siteLongitude(SITE.lon)` and passing both to `utOf(date, hour, lon)` and `venusSky(..., lat, lon)`.
   - Wired `createVenus(...).update(date, hour, ...)` to `siteVenusSky(date, hour)` and included `lat, lon` on `window.__venus` when `?rec` is active, preserving default arguments on `utOf` and `venusSky` for existing callers/tests.
4. **Unit tests & reusable skill (`tests/chronometer-venus-site.test.ts`, `notes/skills/boreal-seasonal-light-audit.md`)**:
   - Added `tests/chronometer-venus-site.test.ts` covering `siteLongitude` fallback/restore, `chronoSunState` & `dialGradient` across winter solstice (`day = 355`), August baseline (`day = 227`), and remote `-23.44°S` landing, plus `siteVenusSky` / `createVenus.update` topocentric Venus & Sun altitude propagation at `(-23.44°S, 15.0°E)`.
   - Documented the reusable audit/fix workflow in `notes/skills/boreal-seasonal-light-audit.md`.
